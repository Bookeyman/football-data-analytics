| Путь | Назначение |
|---|---|
| `.gitignore` | Список локальных файлов, баз данных, секретов и временных артефактов, которые Git не должен добавлять в репозиторий |

## `python/` — обработка данных и аналитические ноутбуки

| Файл | Назначение |
|---|---|
| `json_to_excel.ipynb` | Обработка JSON-файлов с футбольной статистикой с помощью Python и pandas: извлечение записей, преобразование полей, формирование DataFrame и экспорт в Excel. В ноутбуке также есть логика подготовки статистики игроков для разных лиг |
| `match_report.ipynb` | Подключение к SQLite, выбор двух команд и формирование сравнительного отчёта: положение в таблице и последние матчи команд |
| `radar.ipynb` | Получение статистики игроков из SQLite, расчёт показателей на 90 минут и подготовка данных для радарного сравнения игроков одной позиции |

## `sql/database/` — структура и логика SQLite

| Файл | Назначение |
|---|---|
| `01_schema.sql` | DDL-скрипт создания таблиц и структуры базы данных |
| `02_indexes.sql` | Создание индексов для ускорения поиска и соединения данных по часто используемым полям |
| `03_views.sql` | Создание представлений для повторно используемых аналитических выборок: рейтинги игроков, таблицы команд, голевые показатели, EPV, трансферы и другие срезы |
| `04_triggers.sql` | Триггеры для аудита INSERT/UPDATE/DELETE и проверки отдельных правил целостности, включая ограничения для контрактов игроков |

## `sql/analytics/` — аналитические SQL-кейсы

| Файл | Аналитический вопрос |
|---|---|
| `01_team_performance.sql` | Как команды выступают в чемпионате и насколько эффективны в атаке? |
| `02_player_performance.sql` | Кто из игроков показывает лучшие результаты при достаточном игровом времени? |
| `03_player_value_epv.sql` | Кто создаёт наибольшую ценность по EPV и за счёт каких игровых действий? |
| `04_game_state_analysis.sql` | Как команды набирают очки после того, как уступали в счёте, и после выхода вперёд? |
| `05_goal_contribution.sql` | Какие игроки, связки и игровые позиции обеспечивают голевой вклад? |
| `06_transfer_analysis.sql` | Какие входящие трансферы и клубы имеют наибольшие зафиксированные суммы? |

Каждый SQL-кейс включает формулировку задачи, источники данных, запросы, описание ожидаемого результата и краткую интерпретацию. Для выполнения требуется локальная база с соответствующими таблицами и представлениями.

## Важные замечания

- Файл базы данных SQLite намеренно не публикуется в репозитории.
- Скрипты SQL демонстрируют структуру и логику БД, но для их выполнения необходимы исходные данные.
- Ноутбуки используют локальные файлы и/или Google Colab; пути к базе и исходным JSON при запуске могут потребовать настройки под собственную среду.
- Подготовка данных и импорт в SQLite пока частично выполняются вручную.
- Перед публикацией новых данных необходимо учитывать условия использования SofaScore, Understat, xGLab и Transfermarkt.
